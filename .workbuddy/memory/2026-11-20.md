## 修复：定位后不切分组、不滚动

用户反馈点击后界面无变化。排查后做了四点加固（仍需用户在 Chrome 重新加载扩展验证）：
- **时序**：`useDeferredValue(query)` 导致清空搜索后列表晚一帧刷新，滚动回调拿不到卡片。改用 `flushSync` 同步落地所有状态，并在滚动 effect 里用 rAF 逐帧重试（最多 40 帧）直到卡片出现。
- **滚动位置**：原来 `scrollIntoView({block:'nearest'})` 在卡片已部分可见时不滚动；改为直接对 `.bookmark-list` 计算居中位置并 `scrollTo`，fallback 用 `block:'center'`。
- **URL 匹配**：增加完整 URL 指纹（去 hash / www / 尾斜杠、大小写归一、保留 query）+ 忽略 query 的兜底匹配；对缺失 url 的脏数据做保护，避免 find 抛错被误报为「读取标签页失败」。
- **可见性**：定位时关掉 panel / 分组设置 / 标签管理 / 抽屉 / 快速切换面板；高亮延长到 5 秒并加底色；区分「扩展页面」与「普通网页无法定位」提示；未找到时 toast 显示域名。
- 定位时清掉 `focusedId`，避免 5 秒后高亮清除时二次滚动到旧焦点。

### 第三轮：确认是 URL 匹配失败（用户选「没有找到…的书签」+ 侧边栏准星/标签页行内准星）
- 加了三级匹配：完整 URL 指纹（去 hash/www/尾斜杠/大小写，保留 query）→ 忽略 query → 同域名唯一书签兜底（兼容短链跳转/参数改写）。
- 未找到时的 toast 改为显示当前页面具体网址 + 该域名书签条数，便于诊断。
- 构建通过。若仍失败，需要用户给出「当前页面 URL」与「编辑器里看到的书签 URL」对比。

## 主题跟随浏览器（深浅色）
- 根因：主题系统本就支持 `system`（matchMedia 实时跟随），但默认值 `light` 且顶栏按钮/命令面板只在 light↔dark 切换，用户无法选到 system。
- 改动：`DEFAULT_SETTINGS.theme` 改为 `system`；顶栏按钮与命令面板改三态循环 `浅色 → 深色 → 跟随浏览器`，新增 `IconThemeAuto`（半圆图标）；ShortcutsDialog 脚注与 README 同步说明。
- 存量迁移：`loadState` 里用 localStorage 标记 `mn:themeFollowMigrated` 一次性把仍为 `light` 的旧设置切到 `system`（标记保证只改一次，之后尊重用户显式选择）。
- 技术依据：Chrome 120+ 扩展页 `prefers-color-scheme` 跟随浏览器外观模式，change 事件实时响应。
- 构建通过。未提交推送（用户未要求）。
