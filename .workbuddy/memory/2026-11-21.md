## 修复审查发现的 4 个严重问题（提交 cdad674 之后）
经逐行代码审查发现并修复（用户要求「做1到4」）：
1. **清除 PIN 后私密分组永久打不开**：根因 lockedGroupIds 只看 g.private 不看 pinHash，取消 PIN 时不清 private，导致 verifyPin(_, undefined) 恒失败且开关被禁用。修复：store 新增原子 `setPin(hash)`（清除时同步抹掉所有分组 private 标记）；App handleSetPin 改用它并无条件清空 unlockedGroups；lockedGroupIds 加 `!settings.pinHash` 守卫双保险；GroupSettingsDialog 无 PIN 时允许取消残留 private 勾选。
2. **分层存储跨设备丢失**：根因归档书签只写 chrome.storage.local（不跨设备），sync 不含它们，其它设备拉取后书签消失且一旦写入就固化。修复：buildV3Payload 不再过滤 archived（归档也进 sync，一致性优先于省配额）；新增 mergeWithLocalArchive 以 sync 为权威、local 副本只补 favicon 与缺口；更新 README/SettingsDialog/toast 文案——归档仍占 sync 配额但跨设备可见，local 留完整副本兜底。
3. **浏览器新建后立即改名/移动导致书签丢失**：根因 background.js pushBmEvent 用 `evt.type !== 'created'`（判断入站事件）过滤，来 changed 时把已入队 created 删掉，前端按 browserId 找不到即跳过。修复：改为按 nodeId+同类合并（保留 created 基础事件，同类型字段 merge），不再误删。
4. **死链角标打开错误弹窗**：根因角标 onClick 打开 InsightsDialog（无死链出口），真列表在 DataDialog。修复：角标与巡检 alarm 的「立即检测」都改为打开 DataDialog 且 focusHealth=true（自动滚动到书签健康区并跑检测）；DataDialog 新增 focusHealth/onHealthResult props，检测结果与删除回写 healthMonitor.deadIds，与设置页检测统一口径（均排除软删）；deadLinkCount 改用过滤后的 bookmarks。
